# daily-trend

毎日1件だけ技術トレンドを選び、日本語で1分要約して、引用元つきで表示するツール。

## 使い方

| 操作 | 内容 |
|---|---|
| **⌥T**（どのアプリからでも） | 今日の1件をパネル表示。もう一度押すか Esc で閉じる |
| パネルをドラッグ | パネルを移動。位置は覚えていて、次回もそこに出る。メニューの「パネルの位置を元に戻す」で既定の位置に戻る |
| パネル内 `O` / `D` / `←` `→` / `C` | 元記事を開く / 話題元を開く（URL のある最初の話題元）/ 前日・翌日 / 引用元をコピー |
| パネル内 `↑` `↓` / `Space` / `Home` `End` | 長いときのスクロール（下に続きがあると「↓ 続きあり」が出る） |
| `trend` | ターミナルに今日の1件を表示 |
| `trend -e` | 要点の根拠（本文からの抜粋）も表示 |
| `trend open` / `trend buzz` | 元記事 / 話題元（HN・はてブ等）をブラウザで開く |
| `trend cite` | 引用元を Markdown で表示し、クリップボードにコピー |
| `trend ls` / `trend -1` / `trend 2026-09-27` | 過去の一覧 / 前日分 / 指定日 |
| `trend run --force` | 今日の分を別の記事で作り直す。今日すでに出した記事は選ばない |
| `trend run --force --focus blogs` | 種類を絞って作り直す（`news` / `blogs` / `oss` / `papers` / `balanced`）。メニューバーの「種類を指定して生成」でも同じことができる |

生成は毎朝 7:05 に自動で走る（launchd）。スリープ等で逃したら、未生成の間は 22 時まで毎時再試行する。API を呼ぶ試行は1日3回まで。

## 仕組み

1. **候補集め（LLM なし）**: 下の取得元から約400件を集め、同じ記事を統合し、取得元ごとの順位で点数を付ける。過去30日に出した記事は除く。作り直すときは、今日すでに出した記事も除く。各取得元の上位をほぼ同じ件数ずつ、合計60件に絞る。種類を絞っているとき（下の「選ぶ種類」）は、その種類の候補だけを残す。
2. **1件選ぶ（Claude）**: その60件から、`config.toml` の関心の優先順位に沿って3件を推す順に選ぶ。直近7日に出した記事（作り直すときは今日出した記事も）と同じ話題は避けるよう指示する。
3. **本文取得**: 1位の本文を取る（論文は要旨、GitHub のリポジトリは README、issue・PR・リリースはその本文、一般記事は本文抽出）。robots.txt で拒否されている・有料記事などで取れなければ2位、3位へ。
4. **要約（Claude）**: 本文だけを根拠に、見出し・結論1文・要点3つを書く。要点ごとに、根拠となる本文の一節（原文のまま）を付けさせる。
5. **検証**:
   - (a) 根拠の一節が本文に実在するかをコードで照合する。正規化したうえでの完全一致で判定し、省略記号や、数値・単語の途中から始まる引用は不合格にする。
   - (b) 要点・見出し・結論・「なぜ今」の中身が、その一節（と記事の書誌情報）で裏付けられるかを Claude に別途判定させる。
   - どちらかが駄目なら1回だけ書き直させる。それでも残れば ⚠︎ と注意書きを付けて表示する。判定自体に失敗した場合も「未判定」と表示する。
   - 用語の説明だけは本文ではなく一般知識で書くので、そう表示する。
6. **引用元**: 元記事 URL と話題元（HN の議論ページ、はてブのコメントページ等）と数値・取得時刻は、LLM に書かせず候補データからコードで組み立てる。

## 取得元と規約上の扱い（2026-09-28 に実測・規約確認。GitHub 急上昇・テックブログ・公式ブログは 2026-10-02）

| 取得元 | 方法 | 備考 |
|---|---|---|
| Hacker News | Algolia 公開 API（過去24時間の points 上位） | HN 本体の HTML は利用規約でスクレイピング禁止のため使わない |
| GitHub（新しいリポジトリ） | 公式 Search API（30日以内に作成・1日あたりのスター数順） | Trending ページの HTML 取得は GitHub AUP の許可用途外のため使わない |
| GitHub（急上昇） | GitHub の公開イベントを集めた公開データ（GH Archive 由来。ClickHouse の公開プレイグラウンド）で、直近24時間のスター数を数える。説明と累計スター数は公式 Search API | 作成時期を問わず拾える。全件ではなく標本なので、数は「標本内の件数」と表示する。標本が少なすぎる日は使わない |
| Hugging Face | 公開 API（Daily Papers / Trending Models） | 匿名 500回/5分 |
| はてなブックマーク | テクノロジー人気エントリー RSS | X で話題の日本語記事がよく上がる |
| Zenn / Qiita | デイリートレンド API / 人気記事フィード | 本文は保存・転載しない |
| Techmeme | トップページ（robots.txt で許可） | 各話題に付いた X 投稿の数を「X での反応」として使う |
| 企業のテックブログ | 各社が配信している RSS / Atom（`config.toml` の `[feeds.techblogs]`。DeNA・メルカリなど20社） | 7日以内の記事。はてなブックマーク数（公式の件数取得 API）と新しさで並べる。robots.txt で拒否されたフィードは読まない |
| 公式ブログ | 同上（`[feeds.official]`。OpenAI・Google・GitHub・Rust など14個） | 新しいモデル・製品・バージョンの発表を一次情報で拾う |

### X（旧Twitter）について

X は直接の取得元にしていない。

- X の利用規約はスクレイピングを禁止している。robots.txt も一般ボットを全面拒否している。
- Nitter・埋め込み用の内部エンドポイント・トレンド集約サイトは、規約違反か、停止・ブロックされているため使わない。
- 規約内で X を直接検索する方法は、有料の X API（従量課金。Recent Search で1日10件なら月 $1.5〜5 程度）だけ。開発者登録とクレジットの前払いが要る。

代わりに、X で話題になったことを次の形で拾う。
- Techmeme が各ニュースに付けている X の反応投稿の件数（例: 「X 34 件の投稿」）。
- X で話題になった日本語記事は、はてブや Zenn にも上がりやすい。

Reddit も使わない。非認証の API は 403 が返る。規約も、事前の同意がない自動取得を禁止している。
Lobsters も使わない。robots.txt が一般ボットに RSS を含む全パスを拒否している。

本文の取得でも同じ方針をとる。記事ページは robots.txt で許可されている場合だけ取る。GitHub の issue・PR・リリースは公式 API で取る。
取れない記事は飛ばして次点の候補に進む。

## 選ぶ種類

候補は4つの種類に分けている。

| 種類 | 中身 |
|---|---|
| `news` ニュース・発表 | Hacker News / Techmeme / はてブ / 公式ブログ（新しいモデル・製品・バージョンなど） |
| `blogs` テックブログ | Zenn / Qiita / 企業のテックブログ。はてブや HN に出た記事も、ブログのホストなら含める |
| `oss` OSS・公開モデル | GitHub のリポジトリ / Hugging Face のモデル |
| `papers` 論文 | Hugging Face Daily Papers（arXiv） |

- 毎朝の既定は `config.toml` の `[pick] focus`。`"balanced"`（すべて）か、上の種類を1つ書く。
- その回だけ変えるときは `trend run --force --focus blogs`、またはメニューバーの「種類を指定して生成」。
- 重みを付けたいときは `focus = "custom"` にして `[pick.weights]` を書く。大きい種類ほど候補の上位に入る。0 の種類は候補から外れる。

## 設定（`config.toml`）

- `pick.model`: 要約に使うモデル（既定 `claude-opus-5`）。費用を下げるなら `claude-sonnet-5`。
- `pick.interests`: 選ぶときの優先順位。
- `pick.focus` / `pick.weights`: 選ぶ種類（上の「選ぶ種類」）。
- `sources.*`: 取得元の on/off。
- `feeds.techblogs` / `feeds.official`: RSS / Atom で読むブログ。「表示名 = フィードの URL」の行を足したり消したりできる。`feeds.max_age_days` は候補にする記事の新しさ（既定 7 日）。
- `app.hotkey`: パネルを出すキー（今の設定は `"option+t"` = ⌥T。変更後は TrendBar を再起動）。読めない値のときは ⌃⌥T を使い、メニューに理由を出す。
  - ⌥T は英字入力で「†」を打つキー。TrendBar が先に反応するので、この記号はキーボードから打てなくなる。
  - TrendBar はこのキーを exclusive（他のアプリより優先）で登録する。他のアプリが exclusive で同じキーを持っていれば、メニューに「ホットキー登録失敗」と出る。
  - 他のアプリが通常の登録で同じキーを持っている場合は検出できない。そのときは TrendBar だけが反応し、相手のアプリにはキーが届かない。押しても相手のアプリが反応しなくなったら、hotkey を変える。

API キーは `~/.zshenv` の `ANTHROPIC_API_KEY` を使う（launchd からは `zsh -c` 経由で読む）。

データの場所を変えるときは `~/.zshenv` に `export DAILY_TREND_HOME=...` を書く（`data/` と `config.toml` がその下になる）。TrendBar も起動時に `zsh -c` で同じ値を読む。変更後は TrendBar を再起動する。

## 費用の目安

Claude API を1日に3〜7回呼ぶ（選定1回・要約1〜3回・判定1〜3回）。実測では入力 2万〜4.5万トークン、出力 2,000〜3,000 トークン程度。
`claude-opus-5`（入力 $5 / 出力 $25 per 100万トークン）で **1日 約 $0.15〜0.3、月 $4〜9 程度**。
`claude-sonnet-5` に変えると約4割になる。実際のトークン数は `data/logs/` に記録される。

## ファイル

- `data/days/YYYY-MM-DD.json` / `.md`: その日の1件（Markdown はメモアプリにそのまま貼れる）。作り直した日は、置き換える前に出していた記事を JSON の `replaced` に残す（翌日以降も既出として除く）
- `data/candidates/YYYY-MM-DD.json`: その日の候補一覧（選考の記録）
- `data/logs/`: 実行ログ（API のトークン数も記録）

## インストール / アンインストール

### 必要なもの

- macOS 13 以降（Apple シリコン）
- Xcode Command Line Tools（`git` と `swiftc` を使う）: `xcode-select --install`
- [uv](https://docs.astral.sh/uv/)（Python と依存パッケージを入れる）: `brew install uv`
- Anthropic の API キー: `~/.zshenv` に `export ANTHROPIC_API_KEY=...` を書く

### 手順

置き場所は `~/daily-trend` 固定。別の場所に置くと動かない。

```bash
git clone https://github.com/iwatsuki-yuuki/daily-trend.git ~/daily-trend
~/daily-trend/install.sh
```

`install.sh` は次のことをする。

1. `.venv` を作り、`requirements.txt` のパッケージを入れる。
2. `trend` コマンドを `~/.local/bin` に置く。
3. TrendBar.app をビルドする。
4. launchd に登録する（毎朝の生成と TrendBar の常駐）。

`trend` コマンドを使うには `~/.local/bin` に PATH を通す。通っていなければ `~/.zshrc` に `export PATH="$HOME/.local/bin:$PATH"` を足す。

インストール直後はまだ1件も無い。最初の1件は `trend run` か、メニューバーの「今すぐ生成／再生成」で作る（1分ほど）。

### アンインストール

```bash
~/daily-trend/uninstall.sh
```

アンインストールしても `data/` の記録は残る。
